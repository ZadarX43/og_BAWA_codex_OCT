# README_FRONTEND

Updated: `2026-05-04`

## Purpose

This frontend is a static scaffold for the Odds Genius website layer.

It does not run model logic in the browser.
It reads published JSON files generated by the Python export layer.

## Local Preview

Preferred preview command:

```bash
cd frontend
python3 -m http.server 8000
```

Then open:

- `http://127.0.0.1:8000/`
- `http://127.0.0.1:8000/predictions.html`
- `http://127.0.0.1:8000/premium.html`
- `http://127.0.0.1:8000/results.html`
- `http://127.0.0.1:8000/pricing.html`
- `http://127.0.0.1:8000/methodology.html`
- `http://127.0.0.1:8000/account.html`

## JSON Files That Power The Site

The frontend reads:

- `frontend/public/data/public_predictions.json`
- `frontend/public/data/premium_predictions.json`
- `frontend/public/data/publish_summary.json`

Current behavior:

- `predictions.html` uses the public board
- `premium.html` uses internal demo mode for static preview or the Worker premium route when configured and token-authenticated
- `index.html` uses both boards plus publish summary metadata
- `results.html` currently reads `weekly_results.json` for proof rollups; the backend now also publishes `results_archive.json` for the next settled archive UI layer

## Frontend Worker Config

The frontend now reads a small non-secret config file:

- `frontend/assets/config.js`

Current placeholder shape:

```js
window.OG_CONFIG = {
  WORKER_API_BASE: ""
};
```

Use `WORKER_API_BASE` only for the Worker origin or same-origin Worker path.

Examples:

- `https://odds-genius-worker.<subdomain>.workers.dev`
- `/worker`

Do not place any secrets in this file.

## Current Worker-Aware Frontend Behavior

- `pricing.html`
  - upgrade CTA calls `POST /api/stripe/checkout` through the Worker when `WORKER_API_BASE` is configured
  - otherwise falls back to placeholder flow
- `premium.html`
  - fetches `GET /api/premium/predictions` only if a premium token is stored locally
  - no token means locked state
  - `?demo=1` still shows internal static preview mode
- `account.html`
  - explains that developer/test token storage is not public auth
  - provides a local token save/clear panel for controlled Worker testing

## How To Regenerate Predictions

Default latest-source publish:

```bash
python3 publish_predictions.py
```

One-command publish wrapper:

```bash
./scripts/publish_latest_deploy.sh
```

Explicit source publish:

```bash
python3 publish_predictions.py --src predictions_output/<RUN>/02_deploy/DEPLOY_COMBINED_<FROM>_to_<TO>.csv
```

Or with the wrapper:

```bash
./scripts/publish_latest_deploy.sh --src predictions_output/<RUN>/02_deploy/DEPLOY_COMBINED_<FROM>_to_<TO>.csv
```

This writes:

- `frontend/public/data/public_predictions.json`
- `frontend/public/data/premium_predictions.json`
- `frontend/public/data/publish_summary.json`
- `reports/latest/PUBLISH_REPORT.md`

## How To Validate Public Export

Run:

```bash
python3 validate_public_export.py
```

This checks:

- required fields
- unexpected fields
- suspicious paths or model references
- NaN / Infinity
- null critical IDs

## Frontend Static Smoke Check

Run:

```bash
python3 scripts/smoke_frontend_static.py
```

This checks:

- expected HTML files exist
- core assets exist
- published JSON exists
- page asset references are valid
- no HTML file includes forbidden private/internal terms from the export policy

## Deployment Direction

This scaffold is designed to be Cloudflare Pages-friendly later:

- static HTML under `frontend/`
- static assets under `frontend/assets/`
- published JSON under `frontend/public/data/`

Likely later deployment shape:

1. Regenerate exports locally
2. Validate export safety
3. Commit frontend + published JSON
4. Push to GitHub
5. Cloudflare Pages serves `frontend/` as the project root or publish directory
6. Configure `WORKER_API_BASE` so the frontend can hand off secure premium flows to the Worker

## Important Boundary

- Never add deploy logic to the frontend
- Never expose raw model internals
- Never bypass the allowlisted publish layer
- Never present local token storage as final public authentication
