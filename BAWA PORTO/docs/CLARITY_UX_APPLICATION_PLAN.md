# Clarity UX Application Plan

## Purpose

This plan translates the `Clarity Replacing Chaos` brand system into concrete website and product decisions.

It is the bridge between:

- strong backend intelligence architecture
- coherent frontend product experience

The guiding standard is:

> Clarity replacing chaos.

Every website and alert-system decision should support:

- slower thinking
- stronger interpretation
- less impulsive action
- more user agency

## Product Experience Goal

Odds Genius should feel like:

- a calm intelligence desk
- a disciplined football briefing environment
- a decision-support system

It should not feel like:

- a betting room
- a sportsbook
- a tipster blast channel
- an urgency machine

## Core UX Model

The site should consistently move users through:

1. signal
2. interpretation
3. reflection
4. choice

Not:

1. alert
2. excitement
3. impulse
4. action

## Page-Level Application

### Home Page

#### Goal

The homepage should orient, steady, and establish authority.

It should communicate:

- calm intelligence
- selectivity
- disciplined thinking
- structured edge

#### Hero Direction

Use calm, high-trust headline options such as:

- Signal over noise.
- Think better before you bet.
- Clarity under uncertainty.
- Build edge, not dependency.

Supporting copy should emphasize:

- selective deployment
- intelligence over hype
- evidence-led football reading

#### Home Structure

Recommended sections:

1. Hero
2. Today’s signal board
3. Why this matters
4. How the system thinks
5. Reflection / restraint principle
6. Proof layer
7. Pricing / access path

#### Home UX Rules

- no flashing urgency
- no oversized odds-first emphasis
- no “must act now” copy
- no hype language

### Dashboard

#### Goal

The dashboard should become the calm operating surface for followed intelligence.

It should feel like:

- a personal intelligence terminal
- a watchlist and decision desk

#### Recommended Dashboard Hierarchy

1. Critical now
2. High relevance
3. Watch / observe
4. Website-only intelligence
5. My alerts
6. Reflection / reset prompts later

#### Recommended Sections

##### Critical Now

Only show:

- followed fixture
- followed team
- strongest direct deploy relevance

##### Watch Closely

Show:

- relevant `OBSERVE`
- relevant `CONTEXT`
- near-kickoff fixtures with good personal fit

##### Website-Only

Show:

- lower-priority market matches
- monitor states
- useful but non-interruptive intelligence

##### My Alerts

Display:

- queued
- delivered
- failed
- why it was routed
- why it was not routed more aggressively

## Fixture Card Structure

Each fixture card should clearly answer:

- what is this
- why is it relevant
- what supports it
- what weakens it
- what action state it belongs to

### Required Card Fields

- fixture class
- market family
- tier / confidence state
- short headline
- “why this matters”
- “what could weaken it”
- follow reason
- delivery posture

### Recommended Card Framing

#### DEPLOY

Should feel:

- selective
- actionable
- calm

Should show:

- why the edge exists
- why it cleared deployment
- any fragility notes

#### OBSERVE

Should feel:

- useful
- non-urgent
- informational

Should show:

- model lean
- uncertainty
- why it stayed out of deployment

#### MONITOR

Should feel:

- structured
- observational
- calm

Should show:

- fixture context
- team / league relevance
- what is worth keeping an eye on

#### PASS / NO EDGE

Should feel:

- respectable
- disciplined
- complete

Should never feel like:

- empty
- broken
- missing

### PASS / NO EDGE Copy Pattern

Examples:

- No deployable edge detected. Market appears efficiently priced. Monitor only.
- No structured edge is visible here. Useful for awareness, not action.
- Current pricing leaves little room for disciplined entry. Observation only.

## My Feed / My Alerts Priority Presentation

This should become one of the strongest product surfaces.

### Priority Buckets

Recommended buckets:

- Critical
- High relevance
- Watch
- Website only
- No edge / pass

### Priority Inputs

Weight most heavily:

1. followed fixture
2. followed team
3. deploy status
4. timing proximity
5. followed league + market
6. market-only relevance

### UX Rules

- Telegram should only surface stronger interrupt-worthy items
- dashboard can hold broader coverage
- `website only` is a valid and respected state
- low-priority intelligence should still feel useful, not second-class

## Notification Copy And Interruption Rules

### Notification Standard

Every outbound alert should answer:

> Is this worth interrupting the user?

If not:

- keep it on-site
- put it in digest
- place it in a later review bucket

### Telegram Copy Rules

Telegram alerts should:

- be concise
- be calm
- avoid hype
- include context
- link back to deeper fixture intelligence

Avoid:

- pressure
- exaggerated confidence
- social-proof framing
- pseudo-scarcity

### Notification Tiers

#### Immediate

Only for:

- direct followed fixture
- direct followed team
- high-priority deploy
- major change that materially affects judgment

#### Digest

Use for:

- league-level patterns
- lower-priority observe items
- broader market context
- accumulation of smaller intelligence points

#### Website Only

Use for:

- market-only weak relevance
- low-confidence context
- monitor/pass states

## Calm Onboarding / Tipster Detox Flow

### Goal

Help new users move from:

- borrowed conviction
- noisy tipster habits

to:

- structured judgment
- controlled follow preferences
- calmer decision habits

### Recommended Onboarding Steps

1. Choose leagues
2. Choose markets
3. Choose teams
4. Choose notification depth
5. Choose user style
6. Set pacing / cool-off preferences
7. Receive first calm dashboard

### Suggested User Styles

- Analyst
- Disciplined bettor
- Tactical reader
- Researcher

These should shape:

- notification depth
- dashboard density
- explanation style

### Soft Framing

Suggested line:

> Coming from tipster groups? Odds Genius helps replace rented conviction with structured judgment.

## Calm Decision Companion Layer

This can begin as a lightweight panel on fixture pages and later expand.

Suggested prompts:

- What is the edge?
- What could invalidate this?
- Is this structured or impulsive?
- Would I still take this without outside noise?
- Is no action the better decision here?

This should feel like:

- elite discipline
- professional review

Not:

- therapy
- over-explaining

## Reflection Loop

This should become a meaningful retention layer later.

### Post-Result Prompts

- Was the read correct?
- Was the outcome noisy?
- Did the user act from structure or impulse?
- What pattern is emerging?

### Product Goal

Users should feel that Odds Genius improves:

- judgment
- restraint
- self-awareness

not just picks consumed.

## Visual Translation

### Layout

Use:

- generous spacing
- modular cards
- quiet hierarchy
- stable information blocks

### Motion

Use:

- subtle transitions
- restrained emphasis

Avoid:

- celebratory motion
- flashing urgency
- casino-like response patterns

### Color

Use:

- charcoal / graphite / off-black base
- one controlled accent
- minimal danger/success semantics

Avoid:

- hyper-green “profit” language
- aggressive red urgency
- neon sportsbook visual language

The next frontend/product work should focus on:

2. dashboard bucketed priority layout
3. stronger fixture card language for `OBSERVE`, `MONITOR`, and `PASS`
4. `My Alerts` scoring visibility

## Final Standard

Odds Genius should consistently communicate:

- no edge is also information
- restraint is part of edge
- interpretation matters more than stimulation
- users are here to become clearer, not louder

If a future feature increases urgency more than clarity, it is moving the product in the wrong direction.
