# Generated Payload Untrack Plan - 2026-05-22

## Goal

Reduce persistent repo dirt from regenerated website/data payloads without deleting local files or weakening the production prediction spine.

This is an index cleanup plan. It uses `git rm --cached` only, so files stay on disk for local scripts and publish compilers.

## Guardrails

- Do not touch the protected production spine.
- Do not remove files from disk.
- Do not untrack public website fallback files until Worker/R2/D1 coverage is verified.
- Prefer small batches with a status check after each batch.

## Phase 1 - Safe Generated Batch

Untrack these generated families:

- `data_sources/api_football/normalized/`
- `reports/latest/`

Reason:

- These are regenerated by API-football/current-context/report workflows.
- They are large and frequently timestamp/content dirty.
- They are not the production spine.
- They are not required as committed static frontend fallbacks.

Expected command:

```bash
git rm --cached -r data_sources/api_football/normalized reports/latest
```

Verification:

- Confirm representative files still exist locally after untracking.
- Confirm protected production spine remains clean.
- Confirm `git status` shows staged deletions only for this generated batch plus the explicit `.gitignore` and plan-doc changes.
