# Sofascore-Inspired Information Architecture Plan

## Purpose

Define the next website information architecture for Odds Genius using:

- fixture-first navigation
- league-grouped structure
- calm expandable depth
- fast orientation

This plan uses Sofascore as an interaction reference for:

- structure
- navigation
- hierarchy
- clarity

It does not recommend copying:

- sportsbook visual language
- noisy live animation
- ad clutter
- overstimulating status treatment

The goal is:

- Sofascore-like clarity
- merged with Odds Genius intelligence depth
- and the `clarity replacing chaos` product philosophy

## Core Product Position

Odds Genius should feel like:

- a live football intelligence workspace

not:

- a tipster dashboard
- a sportsbook shell
- a giant prediction spreadsheet

The user should be able to understand quickly:

- what fixtures matter
- what state they are in
- why they are relevant
- how deep they want to go

## Core Interaction Principle

Users think in fixtures first.

They do not naturally think first in:

- tables
- pricing grids
- model outputs
- long pick lists

So the product should be restructured around:

1. fixture
2. league
3. status
4. intelligence depth

- Home
- Today
- Live
- Predictions
- Observe

- Following

Optional later:

not:

## Main Feed Structure

The main feed should become:

- fixture-first
- grouped by league
- optionally grouped by date / live state / kickoff band

Recommended primary grouping:

1. date or live state
2. league
3. fixture cards

Recommended immediate group types:

- Live now
- Starting soon
- Today
- Tomorrow

Within each group:

- league sections
- fixture rows/cards

## Right Rail

Desktop should optionally gain a right-hand intelligence rail.

This should be calm, compact, and non-essential.

Recommended widgets:

- weather alerts
- injury / lineup watch
- volatility shifts
- followed teams
- today’s high-priority intelligence
- digest summary

This rail should not become:

- a second noisy feed

It should remain:

- supportive
- glanceable
- low urgency

## Fixture-First Homepage / Feed

The homepage should evolve away from:

- static hero + isolated proof + generic prediction sections

toward:

- a calmer fixture-led home surface

Recommended home hierarchy:

### Top layer

- key live or near-kickoff fixtures
- critical intelligence states
- selective deploy signals
- calm high-value summaries

### Middle layer

- grouped league sections
- followed fixtures
- observe / context watchlist
- why this matters cards

### Lower layer

- deeper proof
- methodology
- results/archive pathways

## Card Depth Model

One of the most important lessons to borrow is:

- collapsed clarity
- expandable depth

Users should not be forced to absorb everything at once.

## Level 1 — Collapsed Card

At first glance, each fixture card should show only:

- fixture
- kickoff / live state
- league
- card state
- market family if relevant
- one-line headline
- personal relevance label

Examples:

- `DEPLOY`
- `OBSERVE`
- `MONITOR`
- `PASS`
- `LIVE`
- `WEATHER`
- `LINEUP SHIFT`

The collapsed card should answer:

- what is this
- why should I care
- is this urgent

## Level 2 — Expanded Interpretation

On expand, show:

- why this reached deployment or observation
- what weakens conviction
- weather
- injury / lineup context
- odds shape
- volatility / fragility
- why this matches the user

This is the interpretation layer.

It should feel:

- intelligent
- calm
- selective

## Level 3 — Deep Intelligence

Only for users who want depth.

This layer can include:

- player props later
- xG / chance-shape later
- overlay summaries
- score-shape views
- tactical notes
- advanced context

This should never be the default surface.

It is a depth layer, not the entry layer.

## Card State System

Every fixture card should resolve into one of these product states:

### `DEPLOY`

Meaning:

- deployable edge is live

Collapsed card should feel:

- selective
- confident
- calm

Expanded layer should show:

- why this reached deployment
- why we may be wrong
- what to do now

### `OBSERVE`

Meaning:

- meaningful model shape exists
- not deployable

Collapsed card should feel:

- useful
- non-urgent
- informative

Expanded layer should show:

- observed shape
- uncertainty
- why it stayed out

### `MONITOR`

Meaning:

- fixture is being tracked
- context matters
- no strong current action state

Collapsed card should feel:

- stable
- low urgency
- awareness-led

### `PASS`

Meaning:

- no deployable edge
- useful to acknowledge explicitly

This is one of the most important states in the system.

Collapsed card should not feel:

- empty
- broken
- second-class

It should feel:

- disciplined
- respectable
- complete

Example language:

- No deployable edge detected. Monitor only.
- Market appears efficiently priced. No structured action state is live.

## League Grouping

League grouping should be one of the strongest layout anchors.

Each group should quickly convey:

- league name
- number of relevant fixtures
- any critical alerts within the group

Optional league header indicators:

- `1 Deploy`
- `2 Observe`
- `1 Weather`

This helps users orient spatially before reading deeply.

## Status Language

Status language should feel:

- active
- calm
- operational

Recommended vocabulary:

- `LIVE`
- `STARTING SOON`
- `DEPLOY`
- `OBSERVE`
- `MONITOR`
- `PASS`
- `WEATHER`
- `LINEUP SHIFT`
- `VOLATILITY`
- `STABLE`

Avoid:

- hype
- betting slang
- urgency phrasing

## Top / Interpretation / Deep Layers

## Top Layer

What belongs here:

- key fixtures
- urgent but calm intelligence states
- strongest deploys
- strongest followed relevance
- live or near-kickoff changes

This layer should be scannable in seconds.

## Interpretation Layer

What belongs here:

- why this matters
- how conviction is framed
- what weakens the read
- relevant context
- route explanation

This layer is the heart of Odds Genius.

It is the difference between:

- information

and:

- intelligence

## Deep Intelligence Layer

What belongs here:

- advanced overlays
- deeper statistical shape
- player-event surfaces later
- model-adjacent supporting context

This layer should stay optional.

## Mobile Interaction Model

Mobile should feel:

- calm
- fast
- digest-like
- swipeable

Recommended principles:

- stacked league groups
- compact cards
- tap to expand
- bottom-first reading comfort
- no over-dense data blocks

Recommended mobile behavior:

- collapsed by default
- expanded on tap
- related fixtures below
- alerts and right-rail content folded into inline modules

## Desktop Interaction Model

Desktop can support:

- left navigation
- central grouped feed
- right intelligence rail

But the center feed must remain dominant.

Do not let desktop become:

- three competing columns of noise

## Design Constraints

The product should borrow:

- Sofascore structure
- not Sofascore emotional tone

Keep:

- calm cards
- clear grouping
- readable spacing
- fixture-first orientation

Avoid:

- sportsbook visual aggression
- excessive motion
- urgency color bias
- flashing live treatments

## Recommended Build Sequence

### Phase 1

- fixture-first dashboard hierarchy
- league-grouped feed sections
- stronger bucket/state headers
- collapsed card-first layout

### Phase 2

- expandable card depth
- clearer `DEPLOY / OBSERVE / MONITOR / PASS`
- right-rail desktop widgets
- better mobile stacking

### Phase 3

- live state modules
- richer deep-intelligence panels
- player/event intelligence later

- a live football intelligence workspace

with:

- fast orientation
- calm grouping
- layered interpretation
- deeper optional intelligence

Instead of:

- a long list of predictions
- a flat account-driven settings product
- a noisy alert board
